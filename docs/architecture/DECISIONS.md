# Registro de decisiones técnicas (ADR)

Estado: `aceptada` | `pendiente` (requiere confirmación del propietario) | `reemplazada`.

| # | Decisión | Estado | Motivo |
|---|---|---|---|
| 001 | Monorepo pnpm workspaces (`apps/*`, `packages/*`) | aceptada | Tipos compartidos entre api/worker/web, un solo CI. |
| 002 | Backend **NestJS** + TypeScript | aceptada (sugerida en el encargo) | Módulos, DI, guards para RBAC, WebSockets y OpenAPI nativos. |
| 003 | PostgreSQL **17** + pgvector | aceptada | n8n 3.x avisa que PG16 es "compatibility support only" y exige ≥17 (comprobado en arranque); Chatwoot exige `vector`. |
| 004 | Prisma ORM + **RLS** en PostgreSQL | aceptada | Defensa en profundidad del aislamiento; rol de app sin BYPASSRLS. |
| 005 | Redis + **BullMQ** para colas | aceptada | Reintentos, backoff, DLQ, idempotencia de jobs. |
| 006 | Dify con el **compose oficial** en proyecto separado | aceptada | 15+ contenedores; reescribirlo crearía deriva en cada actualización. |
| 007 | Dify con **pgvector** en lugar de Weaviate | aceptada | Menos RAM en el Mac; imagen de Docker Hub. Mecanismo oficial (`VECTOR_STORE`, `COMPOSE_PROFILES`). |
| 008 | Evolution con `CORS_ORIGIN="*"` | aceptada | Con lista de orígenes rechaza llamadas sin cabecera Origin (HTTP 500, comprobado). Solo uso servidor-servidor; protección real = API key + red privada. |
| 009 | Proveedor WhatsApp: **Cloud API oficial** + Evolution como adaptador opcional | aceptada (2026-11-10) | Cloud API es oficial y apta para uso comercial; Evolution/Baileys conlleva riesgo de bloqueo. |
| 010 | Orquestación del camino crítico (mensaje → IA → respuesta → pedido) en **worker propio**; n8n para flujos secundarios (notificaciones, stock bajo, alertas, reportes) | aceptada (2026-11-10) | Transacciones, idempotencia y tests automatizados; n8n sigue documentando y ejecutando los 7 flujos donde aporta. |
| 011 | IA: **Dify interpreta y redacta; el backend ejecuta las herramientas** con el tenant de la sesión | aceptada (2026-11-10) | El modelo nunca decide el tenant ni toca la BD; cumple "Dify no es fuente de datos". |
| 012 | Chatwoot: una Account por empresa vía Platform API, inbox de tipo **API**, solo nuestro worker envía a WhatsApp | aceptada | Evita respuestas duplicadas bot/agente y mantiene el control del estado de atención. |
| 013 | Autenticación propia (Argon2id, JWT corto + refresh rotatorio en cookie HttpOnly) | aceptada | Sin dependencia de terceros de pago; control de sesiones y revocación. |
| 014 | Pagos: estructura de planes/límites sin cobros reales | aceptada | Requisito explícito; proveedor (Stripe/Mercado Pago/etc.) se elige después. |
| 015 | Tres roles de BD para la app: propietario (migra), ejecución (RLS) y sistema (BYPASSRLS acotado a login, registro, webhooks y plataforma) | aceptada | RLS sin FORCE para que las migraciones funcionen; la API nunca usa el propietario. |
| 016 | NestJS 12 (ESM) + Vitest + oxlint, validación con Zod 4 vía `StandardSchemaValidationPipe` | aceptada | Versión estable actual de NestJS; esquemas Zod reutilizables en frontend. |
| 017 | Prisma 7 con `@prisma/adapter-pg`; esquema en `database/schema`, migraciones en `database/migrations` | aceptada | Estructura del encargo; cliente generado en cada app. |
| 018 | Stock por variante y sucursal (`stock_levels`) con libro de movimientos inmutable | aceptada | Permite transferencias y multi-sucursal (plan Empresarial). |
| 019 | Login exige correo verificado; refresh token rotatorio con detección de reutilización | aceptada | Seguridad de sesiones. |
| 020 | Base `ai_sales_test` separada para pruebas automatizadas | aceptada | Las pruebas vacían tablas; nunca tocan la base de desarrollo. |
| 021 | La IP real del cliente se toma de `X-Forwarded-For` solo si viene de un proxy de confianza (`TRUST_PROXY`, por defecto `loopback`) | aceptada | La web reenvía `/api` a la API; sin esto todos los usuarios compartirían IP y cupo de intentos de login. En producción el reverse proxy debe **sobrescribir** la cabecera (FASE 8). |
| 022 | Panel web en el mismo origen que la API (rewrite de Next a `/api/v1`), access token solo en memoria, refresh en cookie HttpOnly | aceptada | Sin CORS en el navegador ni tokens en `localStorage`; la cookie CSRF es de doble envío. |
| 023 | Mailpit (MIT) solo en desarrollo, perfil `mail` | aceptada | Probar verificación, invitaciones y recuperación con SMTP real sin enviar correos. En producción se exige un SMTP real. |
| 024 | Cliente identificado por teléfono **o** por el identificador de usuario de WhatsApp (BSUID, `user_id`); `customers.phone` pasa a ser opcional con CHECK de que exista uno de los dos | aceptada | Meta ya envía `user_id` y puede omitir el teléfono. Al enviar a un cliente sin teléfono se usa `recipient` en lugar de `to`. |
| 025 | Cada número de WhatsApp tiene su URL de webhook (`/webhooks/whatsapp/<clave>`), su token de verificación y su App Secret, cifrados con AES-256-GCM; las credenciales se comprueban con Meta antes de guardarse | aceptada | Permite que cada empresa use su propia app de Meta (modo manual) sin mezclar firmas. `WHATSAPP_APP_SECRET` queda para el modo "app de la plataforma" (Embedded Signup, pendiente de la decisión de conexión). |
| 026 | Proceso **worker** separado (`dist/worker.js`) con colas BullMQ 6.5.0 (MIT) en Redis: `wa-inbound` y `wa-outbound`. El webhook solo valida, guarda el evento (clave única) y encola | aceptada | Meta exige respuesta rápida y reintenta hasta 7 días: responder en milisegundos y procesar aparte evita duplicados y pérdidas. Reintentos según los códigos de error oficiales. |
| 027 | n8n recibe eventos desde una **bandeja de salida** (`automation_events`) escrita en la misma transacción del cambio de negocio; el worker la entrega con reintentos y n8n responde llamando a `/api/v1/internal/notify` (idempotente por evento) | aceptada | Ningún aviso se pierde si n8n está caído y ninguno se repite si n8n reintenta. n8n no accede a la base de datos ni modifica inventario o pedidos. |
| 028 | En n8n se mantiene bloqueado `$env` en los nodos (valor por defecto). El token interno se guarda como credencial cifrada de n8n (`services/n8n/setup.sh`) y la URL de vuelta viaja en cada evento | aceptada | Desbloquear `$env` dejaría leer todas las variables del contenedor (incluida `N8N_ENCRYPTION_KEY`) a cualquiera que edite un flujo. |
| 029 | `/api/v1/internal/*` no se publica por la web (excluida del rewrite de Next) y exige token compartido + IP privada, comprobados antes de validar el cuerpo | aceptada | "No exponer servicios administrativos a internet". |
| 030 | Flujos 1, 2, 5 y la parte crítica del 3 y del 6 los ejecuta el worker/backend (decisión del usuario "worker propio, n8n para el resto"); n8n ejecuta las notificaciones de los flujos 3, 4, 6 y la alerta del 7 | aceptada | Las acciones comerciales (pedidos, stock) solo ocurren en el backend, en transacciones e idempotentes. |
| 031 | Chatwoot: cuenta por empresa creada desde Integraciones con la Platform API (usuario técnico administrador + buzón API); secreto del buzón y token cifrados; URL de webhook con clave por empresa y firma HMAC con sello de tiempo (5 min) | aceptada | Aislamiento por empresa en Chatwoot, sin credenciales manuales y sin que Chatwoot hable con Meta (ADR 012). |
| 032 | Copia a Chatwoot en una cola propia `chatwoot-sync` (concurrencia 1, 10 intentos con espera exponencial); un fallo de Chatwoot nunca bloquea WhatsApp | aceptada | El orden de los mensajes se conserva y una caída de Chatwoot no afecta a la atención por WhatsApp. |
| 033 | Acceso de los usuarios del panel a Chatwoot por **inicio de sesión único** (`/platform/api/v1/users/{id}/login`), con rol según el del panel; desactivar o cambiar el rol retira el acceso (`DELETE account_users`) y, si Chatwoot falla, la operación avisa y se puede repetir | aceptada | Sin contraseñas extra y sin accesos que sobrevivan a una baja. |
| 034 | El asistente se pausa cuando un agente responde, se asigna o pospone la conversación en Chatwoot; se reactiva al resolverla o devolverla a pendiente | aceptada | Evita que bot y agente respondan a la vez (riesgo de RISKS.md). |
| 035 | `setup-platform.sh` crea el super administrador y cierra el asistente de instalación de Chatwoot; `SAFE_FETCH_ALLOW_PRIVATE_NETWORK` solo en desarrollo | aceptada | El asistente abierto permite a cualquiera hacerse super administrador; en producción Chatwoot llama a la URL pública de la API. |
